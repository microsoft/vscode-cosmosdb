# Sources without a bundled guide

An unfamiliar engine name is accepted. A guide's absence is not an unsupported-source error.
Inspect selected declarations, metadata, code, documentation, and authorized samples using the
common typed inventory. Establish native identity, routing, shape, relationships, and behavior from
evidence; do not invent SQL, tables, foreign keys, or a supported-engine claim.

Record coverage and provenance, consult authoritative vendor documentation when allowed, and retain
unknown guarantees as `kind:"native", status:"unresolved"` obligations with actionable questions.
Continue unaffected work. Essential missing evidence, actual data loss, and unsupported required
behavior remain real blockers under the issue policy; uncertainty alone is not proof of failure.

For example, a Cassandra-like source may need ordered partition/clustering keys, clustering direction,
static columns, sets/maps/lists, per-cell TTL, write timestamps, counters, lightweight transactions,
and consistency guarantees. Record these as native identities/types and explicit obligations, rather
than translating clustering order into an invented foreign key. No acquisition adapter is required.

Use the common workflow for assessment, ownership, field coverage, executable mappings, target
constraints, approvals, and code-migration handoff. If the bounded mapping examples cannot represent
a required operation, state that tool limitation, propose an explicit reviewed contract extension,
and do not claim unexecuted runtime equivalence or run an arbitrary hook to bypass validation.
